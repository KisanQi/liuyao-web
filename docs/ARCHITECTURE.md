# 架构与规则边界

## 当前结论

项目采用 Vite + TypeScript + 原生 DOM，构建为纯静态站点。现阶段没有账户、数据库或私钥需求，因此不引入 React 与后端。算法固定使用 `mingyu-core@0.1.32` 的 `mingyu-core/divination/liuyao` 公共入口，许可证为 MIT。

核心数据流只有一条：

`问题与期限 → 明确起卦时间/方式 → 确定性排盘 → 用神候选 → 主证与反证 → 应期触发条件 → 稳定 JSON / 页面`

## 分层

1. `parse.ts`：只解析六个 6/7/8/9，固定索引 0 为初爻。
2. `time.ts`：保留实际时间戳，并按固定 UTC+8 计算审计和输入回显时间；不混用 IANA 历史夏令时。
3. `engine.ts`：唯一上游适配入口。每次同步计算前把上游 `timezoneOffset` 重新锁定为 480，只接受 manual/coins，并映射为 `LiuyaoReading 2.2`；应用层补齐可审计的完整纳甲天干。
4. `analysis.ts`：调用上游证据 API，保存候选、事实键、所有权、来源、限制、作用链、反证和应期；摘要只做证据状态归纳。
5. `ui`：只显示稳定协议并收集问题，不参与纳甲、旬空、旺衰或用神计算。

## 规则口径

- 六个爻值按初爻到上爻；6/9 为明动，7/8 为静。
- 纳甲、八宫、世应、伏神和六亲由同一内核生成。
- 变爻六亲沿用本卦宫五行，不按变卦重新定六亲。
- 伏神取本宫首卦中本卦缺失的六亲，并保留所伏爻位。
- 旺相静爻受日冲可判暗动；休囚静爻受日冲判日破，二者不混作明动。
- 月建按节气切换；当前固定北京时间 UTC+8；日柱 23:00 换日。
- 三合当前明确限定为“活跃爻支与日辰／月建共同触发”的日辰三合、月建三合，不宣称覆盖所有流派的一般动爻自成三合。
- 事业默认官鬼为第一候选、父母为文书辅证；财务默认妻财、子孙为财源辅证；感情默认世应双方，不按性别自动硬套妻财/官鬼；通用主题以世应和动变为候选。
- 显式用神优先于主题默认，但盘中无对应本爻/伏神时必须报告未匹配，不得偷换。
- 应期只显示动爻、出空、冲实、伏神透出、反伏吟等触发条件；没有完整日期推演时不输出唯一日期。

完整黄金场景见 `RULESET_CASES.md`。

## 稳定协议与审计

`LiuyaoReading` 当前版本为 `2.2`，包括：

- 原始问题、主题、期限、背景、指定用神；
- 起卦方式、六爻值、逐枚钱币采样；
- 卦局、四柱与计算时区；
- 每爻动静、旺衰、空破、暗动、变爻、伏神；
- 用神候选及逐条引用、支持、限制、作用链、结构、反证、应期与计算步骤；
- 应用级结果 ID/输入哈希，以及单独保留的内核结果 ID/输入哈希和随机重放信息；应用级身份包含问题、期限、背景、指定用神、时间、schema、ruleset 与引擎版本。

应用级哈希是基于规范 JSON 的确定性 128 位身份指纹，用于去重和串案防护，不是防篡改数字签名；若未来用于跨系统签名或法律审计，必须另加服务端 SHA-256/HMAC 或签名链。

`ai-evidence.ts` 从完整 reading 生成只读 `AiEvidenceView 1.1`，对应 `docs/ai-evidence-view.schema.json`。证据包同时携带版本化专业规则，显式要求 AI 引用事实键、展示反证、禁止重算盘面与输出概率/唯一日期；服务端再校验引用存在性和关键证据覆盖。

上游 0.x 升级只能通过 `engine.ts` 适配；协议字段若有破坏性变化必须升级 `schemaVersion`。

## 明确禁止

- UI 或 AI 重新计算纳甲、世应、旬空、六亲和旺衰。
- 用候选数量、支持条数或模型语气生成“成功率”。
- 只展示主证并隐藏空破墓退等反证。
- 把传统类象写成现实身份、疾病、官非或投资结果已被证明。
- 把静卦的同名上游 `changedName` 显示成真实变卦；稳定协议中静卦 `chart.changed` 为 `null`。

## 仍需解决

- 以 `bopo/najia` 或另一合法实现对十个黄金场景做可重复差分，并把明确的流派差异登记为规则表。
- 若开放全球用户，需要让用户显式选择当地民用时区，并定义是否仍统一采用北京时间。
- 对合同、考试、疾病、诉讼、寻物等更细问题建立“语义 → 候选 → 必问信息”矩阵；在矩阵完成前不自动扩张断语。
- AI 只能作为受结构化协议约束的解释层，需另行设计引用、反证和高风险拒答门禁。
